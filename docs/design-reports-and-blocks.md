# Жалобы и блокировки (E-02)

Черновик решения. **Реализация не начата — жду подтверждения.**

## Зачем

Регистрация открыта, лента публичная, писать можно любому, кого нашёл. Google
Play требует от приложений с пользовательским контентом: пожаловаться на
контент и на пользователя, заблокировать пользователя, и чтобы жалобы кто-то
разбирал. Сейчас есть только модерация сообществ целиком (CEO).

## Что видит пользователь

**Заблокировать.** В профиле собеседника и в меню чата — «Заблокировать».
После этого:

- он не может начать с вами новую переписку и написать в существующую
  (сервер отвечает 403, его клиент показывает «Пользователь ограничил
  переписку» — без уточнения, кто кого заблокировал);
- его посты и реакции пропадают из вашей ленты;
- он не виден в поиске для вас, вы — для него;
- звонки от него не доходят.

Блокировка односторонняя и тихая: уведомления заблокированному нет.
Снимается там же, список — в настройках профиля.

**Пожаловаться.** В меню сообщения, поста и профиля — «Пожаловаться»:
причина списком (спам, оскорбления, мошенничество, запрещённый контент,
другое) и необязательный комментарий. После отправки — «Спасибо, мы
посмотрим». Одна и та же жалоба от одного человека на один объект — одна.

**Админка (CEO).** Новая вкладка «Жалобы»: очередь, фильтр по статусу, в
карточке — на что жалоба, текст/пост целиком (для личных сообщений — только
факт жалобы и метаданные, текст зашифрован и сервер его не читает), кто
пожаловался, сколько всего жалоб на этот объект и на этого автора. Действия:
отклонить, удалить контент, предупредить автора, заблокировать аккаунт
(существующие санкции), удалить сообщество.

## Данные

```sql
-- миграция 000050
CREATE TABLE user_blocks (
    blocker_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    blocked_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    PRIMARY KEY (blocker_id, blocked_id),
    CONSTRAINT user_blocks_not_self CHECK (blocker_id <> blocked_id)
);
CREATE INDEX idx_user_blocks_blocked ON user_blocks (blocked_id);

CREATE TABLE reports (
    id           UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    reporter_id  UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    -- на что жалуются: 'user' | 'message' | 'post' | 'community'
    target_kind  VARCHAR(16) NOT NULL,
    target_id    UUID NOT NULL,
    -- автор объекта на момент жалобы: чтобы считать жалобы на человека,
    -- даже если объект потом удалили
    target_owner UUID REFERENCES users(id) ON DELETE SET NULL,
    reason       VARCHAR(32) NOT NULL,
    comment      TEXT,
    -- 'open' | 'resolved' | 'rejected'
    status       VARCHAR(16) NOT NULL DEFAULT 'open',
    resolved_by  UUID REFERENCES users(id),
    resolved_at  TIMESTAMPTZ,
    created_at   TIMESTAMPTZ NOT NULL DEFAULT now(),
    UNIQUE (reporter_id, target_kind, target_id)
);
CREATE INDEX idx_reports_open ON reports (status, created_at DESC);
```

## Где применяется блокировка

| Место | Что меняется |
|---|---|
| `POST /chats` (новая переписка) | 403, если любой из двоих заблокировал другого |
| Отправка сообщения (REST и WS) | 403 в личном чате при блокировке |
| Лента и стена сообщества | посты заблокированных не показываются |
| Поиск людей | друг друга не находят |
| Звонки (`call.invite`) | сигнал не доставляется |
| Реакции | реакция заблокированного не видна и не весит в ранжировании |

Списки блокировок читаются пачкой и кэшируются в Redis на короткое время —
иначе каждая выдача ленты превратится в лишний запрос на каждый пост.

## API

| Метод | Путь | Кто |
|---|---|---|
| `POST /users/{id}/block`, `DELETE /users/{id}/block` | любой | заблокировать/разблокировать |
| `GET /users/me/blocks` | любой | свой список |
| `POST /reports` | любой (лимит: 10/час на аккаунт) | пожаловаться |
| `GET /admin/reports`, `POST /admin/reports/{id}/resolve` | CEO | очередь и решение |

Жалоба на личное сообщение передаёт серверу только идентификатор и метаданные;
текст остаётся зашифрованным. В карточке админки это видно прямо: «текст
недоступен — сквозное шифрование».

## Как это проверяется тестами

- Заблокированный не открывает новую переписку и не пишет в старую → 403.
- Его посты исчезают из ленты жалобщика и остаются у остальных.
- Друг друга не находят в поиске; звонок не доходит.
- Блокировка односторонняя: заблокировавший по-прежнему видит свои старые
  сообщения, заблокированный не получает уведомления.
- Повторная жалоба на тот же объект не создаёт вторую строку.
- Очередь жалоб доступна только CEO (тест обхода `chi.Walk`, как в админке).
- Лимит жалоб: 11-я за час → 429 с `Retry-After`.

## Что нужно решить (вопросы к вам)

1. **Разбирает жалобы только CEO?** Пока в проекте один уровень модерации.
   Можно позже дать право уровням 1–3.
2. **Автоматика по количеству жалоб**: скрывать пост после N жалоб от разных
   людей до решения CEO? Рекомендую: с 5 жалоб — скрыть из ленты, автору
   видно, CEO решает. Без этого один спамер живёт до ручного разбора.
3. **Личные сообщения**: подтверждаете, что сервер не расшифровывает их даже
   по жалобе? Тогда для ЛС остаются только блокировка и санкции по аккаунту.
4. **Уведомление о решении** тому, кто пожаловался: нужно или нет?
   Рекомендую короткое «жалоба рассмотрена» без подробностей.

## Оценка

Две части: блокировки (миграция, применение в пяти местах, UI) и жалобы
(миграция, API, вкладка в админке). Каждая — отдельный коммит с тестами.
