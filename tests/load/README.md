# Нагрузочные сценарии (k6)

Два сценария по горячим путям KISY: REST (отправка/чтение сообщений, список
чатов, поиск) и WebSocket (одновременные сокеты с presence/typing и замером
доставки события обратно клиенту).

> **Никогда не гоняй это против прода.** Нагрузка сожжёт лимиты бесплатных
> Neon/Render и положит рабочий сайт. Только локальный или staging-стек.

## Как запустить

Поднять изолированный стек (свой project name, чтобы не задеть тома соседних
проектов, и свободный порт):

```bash
NGINX_HTTP_PORT=8081 docker compose -p kisyload -f docker-compose.yml up -d
```

Прогнать сценарий (k6 берётся образом, ставить не нужно):

```bash
make loadtest CEO_PASSWORD='<BOOTSTRAP_CEO_PASSWORD этого стека>'
make loadtest SCENARIO=ws VUS=100 DURATION=1m CEO_PASSWORD='…'
```

Переменные: `SCENARIO` (`rest`|`ws`), `BASE_URL`, `VUS`, `DURATION`, `USERS`,
`HOLD_SECONDS` (только ws), `CEO_USER`, `CEO_PASSWORD`.

## Пороги приёмки

| Метрика | Порог | Откуда |
|---|---|---|
| `http_req_duration` p95 | < 200 мс | Definition of Done проекта |
| `http_req_failed` | < 1% | — |
| `kisy_ws_delivery_ms` p95 | < 500 мс | лаг фан-аута заметен в UI |
| `kisy_ws_delivery_success` | > 95% | доставка своего же сообщения обратно |

## Важные ограничения (проверено на практике)

- **Auth rate-limit ограничивает сидинг.** `/auth/register` — 5/мин,
  `/auth/login` — 10/мин на IP. Поэтому `USERS` держи ≤ 5: сценарии специально
  разводят много VU по нескольким сессиям (`__VU % users.length`), что и так
  реалистично — один пользователь параллельно шлёт из нескольких вкладок.
  Частые повторные прогоны подряд могут упереться в окно логина: подожди
  минуту. Пользователи переиспользуются между прогонами (сидинг идемпотентный).
- **Заголовок `Origin` слать нельзя.** k6 — не браузер; CSRF-мидлварь и
  WS-чекер намеренно пропускают запросы без `Origin`. Если его выставить,
  edge-прокси нормализует `Host` без порта и проверка не сойдётся → 403.
- **Чат открывает CEO.** `access.CanInitiateChat` пускает только «сверху вниз»
  (уровень инициатора ≤ уровня цели), а свежий приглашённый — самый слабый.
- Фреймы WS имеют вид `{event, data}` (не `type`), тело сообщения — `data.text`.
